# sdm660-mainline kernel configuration review

## Normalization adjustments
- Converted several manual `=n` toggles to the standard commented-out form expected by the mobile-nixos normalization tooling (KALLSYMS_ALL, HIBERNATION, BLOCK_LEGACY_AUTOLOAD, MAGIC_SYSRQ).
- No functional changes were introduced by this cleanup; the options remain disabled, but the config now mirrors the style generated by `kernel-normalize-config`.

## Delta versus the mobile-nixos baseline
- Keeps legacy block device autoloading disabled, preventing uevent-triggered loading of unwanted block drivers during early boot.
- Enables the Qualcomm fuel gauge (`CONFIG_BATTERY_QCOM_FG=m`) to pair with `CONFIG_BATTERY_QCOM_BATTMGR=m`.
- Trims optional USB gadget functions (ACM, OBEX, UAC1, MIDI, printer, ECM subset) so that only the compositions we actively expose remain in the image.
- Adds arm64 SHA accelerators (`CONFIG_CRYPTO_SHA{1,256,512}_ARM64{,_CE}`) to match upstream expectations for accelerated hashing.

## PostmarketOS (xiaomi-lavender) comparison
- The postmarketOS sdm660 kernel leaves MD RAID (`CONFIG_BLK_DEV_MD=y`) and legacy block autoload (`CONFIG_BLOCK_LEGACY_AUTOLOAD=y`) enabled, whereas our config keeps them off to minimize initramfs footprint and avoid accidental activation.
- postmarketOS ships additional USB composite functions (ACM, OBEX, MIDI, printer) for developer convenience; we restrict these to reduce gadget surface area during early boot.
- Both configurations ship the Qualcomm fuel gauge and SHA512 arm64 crypto modules, so there is feature parity for battery reporting and cryptography despite the differing defaults elsewhere.

## Recommended follow-up
- Once nix tooling is available, re-run `bin/kernel-normalize-config sdm660-mainline --only-check` to confirm no further drift from the autogenerated baseline.
